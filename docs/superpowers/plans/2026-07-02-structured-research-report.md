## 2. Solution Design

### 2.1 报告结构设计

**新的报告结构：**

```markdown
# {公司名称}招股书研究报告

## {二级标题 1：业务定位相关，自然表达}
（2-3 段自然段落，融入背景知识）

## {二级标题 2：能力分析相关，自然表达}
（3-4 段自然段落，展开技术和规模）

## {二级标题 3：财务张力相关，自然表达}
（2-3 段自然段落，展开权衡逻辑）

## {二级标题 4：读者价值相关，自然表达}

### 如果你是该行业的从业者
（2-3 段，可操作洞察）

### 如果你是消费者
（2-3 段，购买建议）

### 这份招股书揭示的趋势
（5-6 段，1,400-1,800 字）
- 技术演进位置
- 产业链影响
- 个人影响
- 更大图景
```

**关键点：**
- 二级标题用自然表达（"把 AI 能力装进硬件的路径选择"，不是"业务定位"）
- 标题下保持自然段落（不用"技术能力：xxx"这种格式）
- 大幅增加内容深度（每个点都展开讲）
- 融入背景知识（但不写成科普）

### 2.2 目标长度分配

| 章节 | 当前字数 | 目标字数 | 增量 |
|------|---------|---------|------|
| 业务定位 | 200 | 400-500 | +200-300 |
| 能力分析 | 300 | 600-800 | +300-500 |
| 财务张力 | 200 | 400-500 | +200-300 |
| 读者价值 | 500 | 1,200-1,700 | +700-1,200 |
| **总计** | **1,200** | **2,600-3,500** | **+1,400-2,300** |

**重点增量：读者价值部分（特别是趋势分析）**

### Step 2: Update `reader_value_translate` Skill

修改 `skill_executor.py` 中的 `_execute_reader_value_translate`：

```python
def _execute_reader_value_translate(
    evidence_items: list[EvidenceItem],
    citation_index: dict[str, str],
) -> SkillInterpretation:
    """
    读者价值翻译（深度版）
    
    不是简单的"投资人看什么、技术人看什么"，而是：
    - 从业者：可操作的机会窗口
    - 消费者：具体的购买建议
    - 趋势：宏观的产业洞察（1,400-1,800 字）
    """
    from ipo_evidence.llm_caller import call_claude_for_skill
    
    # 1. 证据筛选
    relevant = [
        item for item in evidence_items
        if any(kw in item.text for kw in ["产品", "收入", "研发", "客户", "风险", "技术", "市场"])
    ]
    relevant = _deduplicate_evidence(relevant)
    relevant = _limit_evidence(relevant, max_count=15)
    
    if len(relevant) < 3:
        return SkillInterpretation(
            skill_key="reader_value_translate",
            interpretation={},
            evidence_chain=[],
            confidence="low",
            gaps=[{"gap": "读者价值相关证据不足", "impact": "无法提供深度洞察"}]
        )
    
    # 2. 构建证据文本
    evidence_text = "\n\n".join([
        f"[{citation_index.get(item.evidence_id, '?')}] {item.claim_summary[:200]}"
        for item in relevant
    ])
    
    # 3. 构建 prompt（深度版）
    instruction = """你是招股书分析专家。根据以下证据，为不同读者提供可操作的洞察：

1. **如果你是该行业的从业者（创业者、产品经理）**：
   - 这家公司占据了什么位置？（市场地位、客户结构）
   - 它的短板在哪里？（这是你的机会窗口）
   - 它选择的路径说明了什么？（已验证的模式 or 需要避开的坑）
   - 给出 2-3 条具体的、可操作的建议

2. **如果你是消费者**：
   - 应该买还是不买该公司或相关公司的产品？
   - 如果买，怎么判断产品质量？（看什么指标）
   - 如果不买，为什么？（基于技术成熟度或商业模式）
   - 给出具体的购买建议

3. **这份招股书揭示的趋势（重点，需要深度分析）**：
   
   a) 技术演进位置（200-300 字）：
      - 这个技术在整个人机交互范式迁移中的位置
      - 为什么会出现这个趋势？（技术、监管、成本哪些因素推动）
      - 这个趋势处于什么阶段？（炒作期 / 爬坡期 / 稳定期）
   
   b) 产业链影响（300-400 字）：
      - 对上游（芯片厂商、技术提供商）的影响
      - 对下游（硬件厂商、应用开发商）的影响
      - 产业分工如何重构？（谁的话语权在上升，谁在被挤压）
   
   c) 个人影响（200-300 字）：
      - 对职业选择的影响（哪些岗位价值在上升，哪些在分化）
      - 对消费决策的影响（什么时候买，什么时候等）
   
   d) 更大图景（300-400 字）：
      - AI 能力的商品化路径（云端 API vs 端侧模组）
      - 产业演化类比（像摄像头产业链、触摸屏普及过程）
      - 对创业方向的启示（做什么、不做什么）

要求：
- 具体到这家公司的特征，不要泛化（例如：不要说"对话式 AI 很重要"，而要说"思必驰在车载市场排第二，说明..."）
- 给出可操作的建议（做什么、不做什么、买什么、不买什么）
- 融入背景知识，但不要写成科普（用"这意味着..."、"背后的逻辑是..."这样的过渡）
- 用类比帮助理解（"就像摄像头产业链的演化..."）
- 趋势部分要有深度，展开讲（1,400-1,800 字）

输出 JSON 格式：
{
  "for_practitioners": "从业者价值（200-300 字，2-3 条可操作建议）",
  "for_consumers": "消费者价值（200-300 字，具体购买建议）",
  "trend_tech_position": "技术演进位置（200-300 字）",
  "trend_industry_impact": "产业链影响（300-400 字）",
  "trend_personal_impact": "个人影响（200-300 字）",
  "trend_big_picture": "更大图景（300-400 字）"
}

不要输出任何解释，只输出 JSON。"""
    
    # 4. 调用 LLM
    try:
        response = call_claude_for_skill(
            skill_name="reader_value_translate",
            evidence_text=evidence_text,
            instruction=instruction,
            max_tokens=3000,  # 增加 token 限制
        )
        
        interpretation = json.loads(response)
        
        return SkillInterpretation(
            skill_key="reader_value_translate",
            interpretation=interpretation,
            evidence_chain=[item.evidence_id for item in relevant],
            confidence="high",
            gaps=[],
        )
    except (json.JSONDecodeError, RuntimeError) as e:
        return _execute_reader_value_translate_fallback(relevant, citation_index)
```

### Step 3: Update `narrative_engine.py`

```python
def _build_user_prompt(
    narrative_materials: dict[str, dict[str, Any]],
    skill_citations: dict[str, list[str]],
) -> str:
    """构建 user prompt（结构化研报版）"""
    
    sections = []
    
    # 业务定位章节
    if "business_goal_decompose" in narrative_materials:
        business = narrative_materials["business_goal_decompose"]
        citations = skill_citations.get("business_goal_decompose", [])
        sections.append(f"""
## 第一章：业务定位

请根据以下信息，写一个二级标题（自然表达）和 2-3 段内容（400-500 字）：

核心业务目标: {business.get('business_goal', 'N/A')}
产品入口: {', '.join(business.get('product_entry', [])[:5])}
目标场景: {', '.join(business.get('target_scenario', [])[:5])}
客户类型: {business.get('customer_type', 'N/A')}
可用 citation: {', '.join(citations[:8])}

要求：
- 二级标题：根据核心业务目标，总结成一句话或短语（例如："把 AI 能力装进硬件的路径选择"）
- 第 1 段：公司做什么（产品、场景、客户）
- 第 2 段：为什么选这条路（融入背景：为什么对话式 AI 需要全栈能力）
- 第 3 段（可选）：这条路的特征和门槛
""")
    
    # 能力分析章节
    if "capability_match" in narrative_materials:
        capability = narrative_materials["capability_match"]
        citations = skill_citations.get("capability_match", [])
        strengths = capability.get("strengths", [])
        weaknesses = capability.get("weaknesses", [])
        tension = capability.get("tension", "")
        
        sections.append(f"""
## 第二章：能力分析

请根据以下信息，写一个二级标题（自然表达）和 3-4 段内容（600-800 字）：

能力强项: {'; '.join(str(s) for s in strengths[:5])}
能力弱项: {'; '.join(str(w) for w in weaknesses[:5])}
核心张力: {tension}
可用 citation: {', '.join(citations[:10])}

要求：
- 二级标题：根据核心张力，总结成一句话（例如："技术全栈和规模验证，但交付仍然重"）
- 第 1 段：技术能力（算法、端侧、交付）
- 第 2 段：为什么需要全栈（融入背景：端侧智能的难点）
- 第 3 段：规模验证（用数据支撑）
- 第 4 段：能力短板和约束
""")
    
    # 财务张力章节
    if "tension_expand" in narrative_materials:
        tension = narrative_materials["tension_expand"]
        citations = skill_citations.get("tension_expand", [])
        
        sections.append(f"""
## 第三章：财务张力

请根据以下信息，写一个二级标题（自然表达）和 2-3 段内容（400-500 字）：

张力点: {tension.get('tension_point', 'N/A')}
正面因素: {tension.get('positive_side', 'N/A')[:200]}
负面因素: {tension.get('negative_side', 'N/A')[:200]}
权衡逻辑: {tension.get('tradeoff_logic', 'N/A')[:200]}
可用 citation: {', '.join(citations[:8])}

要求：
- 二级标题：根据张力点，总结成一句话（例如："技术领先与盈利压力的同步存在"）
- 第 1 段：财务数据（亏损、现金流、研发投入）
- 第 2 段：为什么会亏损（展开权衡逻辑）
- 第 3 段：这种模式的风险和机会
""")
    
    # 读者价值章节（重点）
    if "reader_value_translate" in narrative_materials:
        reader = narrative_materials["reader_value_translate"]
        
        sections.append(f"""
## 第四章：读者价值（重点章节）

请根据以下信息，写一个二级标题和三个三级标题，共 5-7 段内容（1,200-1,700 字）：

从业者价值: {reader.get('for_practitioners', 'N/A')[:300]}
消费者价值: {reader.get('for_consumers', 'N/A')[:300]}
技术演进位置: {reader.get('trend_tech_position', 'N/A')[:400]}
```

```markdown
为什么会亏损？对话式 AI 和端侧智能的规模化落地需要长期投入算法、端侧部署、硬件生产和客户生态建设，因此公司必须在尚未稳定盈利前持续投入研发、人员、采购和市场拓展。这些投入构成未来技术壁垒和产品升级的来源，但也同步造成亏损、现金流压力和业绩波动，形成"技术领先投入越重，短期财务承压越明显"的张力[C-006][C-008][C-009]。

这种模式的风险和机会并存。风险在于，如果商业化放量不及预期，持续投入可能进一步压制盈利和现金流；软硬一体化和自主生产提升交付能力，但也增加供应链、采购和产能管理压力[C-014]。机会在于，如果技术和募投项目顺利转化为规模化订单，收入增长能够覆盖研发及生产投入，亏损可以继续收窄并逐步改善经营现金流[C-010]。

### 如果你是该行业的从业者

这家公司已经占据了车载智能语音市场的第二位，前五大客户是华为、小米、阿里这样的平台型玩家[C-011]。这说明在智能硬件的人机交互层，"大客户 + 定制交付"路径已经被验证，但同时也暴露了两个机会窗口：

不要直接买思必驰品牌的产品——它不是面向消费者的公司，而是 B2B 供应商。但如果你在选华为、小米、阿里、比亚迪的智能设备，可以关注产品详情页有没有提到"思必驰语音方案"或"DUI 平台"[C-006]。这说明背后有一套经过大规模验证的对话系统（2,500 万辆车）[C-011]，体验会比那些用开源方案拼凑的产品更稳定。

### 这份招股书揭示的趋势

对话式 AI 不是孤立的技术赛道，而是"人机交互范式迁移"的一环。从键盘鼠标到触摸屏用了 30 年，从触摸屏到语音交互可能只需要 10 年。思必驰这样的公司，本质上是在解决"下一代交互入口"的工程化问题。

这个迁移不是线性的，而是被三股力量同时推动：**硬件算力下放**（手机芯片的 NPU 算力已经足够跑中等规模的语音模型）、**大模型普及**（ChatGPT 之后，用户对"对话理解"的预期被拉高了）、**场景渗透**（车载、会议、家居这些场景，键盘和触摸屏都不适用）。但这个迁移也被两个现实约束：**端侧能力边界**（再强的芯片也跑不了 GPT-4 级别的模型）、**云端成本压力**（每次唤醒都调 API，硬件厂商付不起这个账单）。

所以你会看到一个分化：通用对话（聊天、搜索）还在云端，场景对话（开车、开会）已经下沉到端侧。思必驰选的是后者，这说明他们判断"场景对话"会比"通用对话"更早规模化——因为前者的准确度要求更低（只需要识别指令），但场景价值更高（安全、隐私、离线）。

端侧智能的兴起，会重构整个对话式 AI 的产业分工。**芯片厂商**（高通、联发科、海思）的话语权在上升。以前语音识别在云端，芯片只是"传输管道"；现在模型要跑在芯片上，NPU 的性能直接决定体验。这就是为什么思必驰招股书里反复提"多芯片适配"[C-003]——不是炫技，而是说"我们已经和主流芯片厂商建立了合作关系"。

**纯云端方案商**（科大讯飞的云服务、百度的语音 API）会被挤压。车企不愿意每次唤醒都调你的云，因为这意味着：(1) 数据被你看到，(2) 没网就不能用，(3) 每辆车每月都要付费。所以你会看到，车载智能语音市场，思必驰（端侧方案）装机量排第二[C-011]，科大讯飞（云端方案）虽然品牌更大，但在前装市场并没有压倒性优势。

**硬件厂商**（华为、小米、比亚迪）的选择逻辑在变。以前买语音方案，主要看识别准确率；现在要看三件事：(1) 能不能适配我用的芯片，(2) 能不能离线跑，(3) 能不能定制（因为每家的产品交互逻辑不一样）。这就是为什么思必驰的收入结构里，"定制开发服务"占比很高[C-006]——不是他们不想做标准品，而是市场还没到标准化阶段。

如果你在思考职业方向：**算法工程师**的价值在分化。纯做"云端大模型"的算法岗，未来会越来越卷（因为 OpenAI、Anthropic 已经把天花板顶得很高）。但"端侧模型压缩和适配"是个新方向——如何把 10 亿参数的模型压到 1 亿还能保持 90% 的效果，如何在不同芯片上调优，这些是工程化 know-how，不是纯算法竞赛能训练出来的。

**产品经理**要理解场景价值。语音交互不是"能用就行"，而是"在什么场景下，它比触摸屏更好"。车载场景是最成熟的（因为开车时不能看屏幕），会议场景在验证中（因为会议纪要有明确价值），家居场景还在摸索（因为很多人觉得对着音箱说话很傻）。如果你做智能硬件产品，不要盲目加语音功能，要先想清楚"用户为什么要用语音而不是触摸屏"。

往更大了说，思必驰这份招股书揭示的不只是"端侧智能"，而是"AI 能力的商品化路径"。大模型出来之后，很多人以为"AI 能力"会像"云计算"一样，通过 API 售卖。但现实是，很多场景不接受 API 模式——要么是隐私不允许（医疗、金融），要么是网络不允许（车载、工业），要么是成本不允许（消费硬件）。

所以你会看到两条平行的路径：**云端 AI**（OpenAI、Anthropic、Google，做通用能力，卖 API）和**端侧 AI**（思必驰、地平线、寒武纪，做场景能力，卖模组或解决方案）。这两条路未来不是谁取代谁，而是各自占领不同场景。通用任务（写代码、写文章、复杂推理）会在云端，场景任务（开车、开会、控制家电）会在端侧。

这对整个科技产业的影响是：**AI 能力会像"摄像头"一样，变成硬件的标配模块，而不是像"搜索引擎"一样，变成中心化的云服务。** 摄像头产业链是怎么演化的？一开始是 Sony、Samsung 做传感器，后来 OV、舜宇光学做模组，再后来每家手机厂商都有自己的影像算法团队。AI 能力的商品化路径可能也是这样：一开始是 OpenAI、Google 做基础模型，现在是思必驰、地平线做端侧适配，未来每家硬件厂商都会有自己的 AI 工程化团队。

如果你在思考创业方向，这个类比很重要：**不要去做"AI 时代的 Google"（通用能力，赢家通吃），而是做"AI 时代的 OV"（场景模组，长尾市场）。**
```
