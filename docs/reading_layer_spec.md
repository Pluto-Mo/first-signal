# 解读层规范：First Signal Prospectus Method

这份规范用于约束 `configs/report_prompt.yaml` 和报告生成器中的 prompt / skill 设计。目标是把招股说明书从“整本总结”转成“第一信号 -> 证据验证 -> 能力链判断 -> 读者可用结论”的稳定流程。

## 1. 核心方法

第一信号指产品表现、渠道动作、增长叙事、用户反馈、募投方向或披露空白中出现的不协调现象。它的作用是把阅读问题收束成一个可验证问题，例如：

```text
产品争议 -> 招股书显示相关软件人才储备薄弱 -> 执行能力不足 -> 消费者观望 / 技术人看到职业机会 / 投资人继续核查
```

招股书解读不直接输出“公司好坏”，而是沿着一条证据链生成判断：

```text
第一信号
  -> 招股书证据
  -> 能力要求
  -> 资源配置
  -> 客户和渠道验证
  -> 风险与披露边界
  -> 不同读者的可用结论
```

## 2. 四个固定 skill

### signal_detection

把外部现象、产品争议、渠道动作、增长叙事或披露空白转化为一个可验证问题。

输入材料：业务描述、产品场景、行业趋势、风险因素、外部现象备注。

输出要求：只生成一个主问题，并说明这个问题需要后续哪类证据验证。

### capability_chain

把产品目标拆成能力要求，再追到团队、研发、客户、渠道、募投和风险。

输入材料：主营业务、产品体系、核心技术、研发费用、研发人员、客户结构、募投项目。

输出要求：写成“产品目标 -> 能力要求 -> 资源配置 -> 客户验证 -> 执行约束”。

### disclosure_gap_scan

把重要但缺席的信息标记为待核查信号，并限制表达强度。

输入材料：渠道、平台、客户、产品线、风险、关联交易、管理层讨论。

输出要求：披露空白只能形成“待核查任务”，不能被写成已经发生的事实。

### reader_value_map

把同一组证据翻译给投资人、行业从业者、技术产品人和消费者。

输入材料：产品、客户、费用、现金流、募投、风险、披露空白。

输出要求：不同读者的结论必须共享底层证据，不输出投资建议、法律意见或审计结论。

## 3. 证据纪律

事实判断必须来自 `evidence_packet.items`，并在报告里生成 `[C-001]` 这类 citation。

推断必须说明证据如何支撑，禁止把行业趋势直接写成公司确定性增长。

披露空白必须保留为核查任务，例如“需要继续核查渠道收入占比、平台数据和管理层口径”。

消费建议需要产品证据、风险证据或外部产品证据支撑。当前文档包没有外部产品证据时，报告只能写“继续核查”。

## 4. 输出结构

报告固定四段：

```text
一、现象入口与核心问题
二、业务、能力与资源匹配
三、披露空白与风险约束
四、不同读者的可用结论
```

这四段分别对应 `configs/report_prompt.yaml` 中的四个 `input_views`：

```text
signal_and_question
business_capability_chain
disclosure_gap_and_risk
reader_action_map
```

## 5. 质量检查

生成报告后检查以下内容：

```text
是否有第一信号
是否有 citation
是否区分事实、推断和可用结论
是否把披露空白写成待核查任务
是否避免具体公司硬编码表达
是否把同一组证据翻译给不同读者
```
